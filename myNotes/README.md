# Работа с текстом в редакторах: основные горячие клавиши

## Навигация и перемещение каретки

* `Home` / `End` (на Mac: `Cmd + ←` / `Cmd + →`) — быстрый переход в начало или конец текущей строки.
* `Page Up` / `Page Down` (на Mac: `Fn + ↑` / `Fn + ↓`) — скролл документа на один экран вверх или вниз.
* `Ctrl + Home` / `Ctrl + End` (на Mac: `Cmd + ↑` / `Cmd + ↓`) — мгновенный прыжок в самый старт или финал файла.
* `Ctrl + ←` / `Ctrl + →` (на Mac: `Option + ←` / `Option + →`) — шаг курсора по целым словам.

## Выделение фрагментов

* `Ctrl + A` (на Mac: `Cmd + A`) — выбрать всё содержимое документа разом.
* `Shift + ←` / `Shift + →` — посимвольный захват текста.
* `Ctrl + Shift + ←` / `Ctrl + Shift + →` (на Mac: `Option + Shift + ←` / `Option + Shift + →`) — выделение текста блоками по словам.
* `Shift + ↑` / `Shift + ↓` — выделение строк вверх или вниз от позиции курсора.
* `Cmd + Shift + ←` / `Cmd + Shift + →` (только Mac) — быстро выделить всю строку до начала или конца.

## История правок и сохранение

* `Ctrl + S` (на Mac: `Cmd + S`) — сохранить текущие изменения в файл.
* `Ctrl + Z` (на Mac: `Cmd + Z`) — отменить последнее действие.
* `Ctrl + Y` или `Ctrl + Shift + Z` (на Mac: `Cmd + Shift + Z`) — повторить отменённую правку.

## Форматирование отступов

* `Tab` — добавление отступа (обычно шаг в 2–4 пробела в зависимости от настроек редактора).
* `Shift + Tab` — уменьшение уровня отступа текущей строки или целого выделенного блокапше

## 🚀 Быстрый старт

Практически все примеры собираются и запускаются по одной схеме:

```bash
# Перейти в папку с нужным примером
cd <folder-name>

# Собрать образ
docker build -t <folder-name> .

# Запустить контейнер
docker run --rm -it <folder-name>
```

В каждой подпапке смотри свой `Dockerfile` и дополнительные заметки по настройке (открытые порты, переменные окружения) — требования отличаются от языка к языку.

## 📚 Шпаргалка по теории Docker

Краткий справочник по концепциям, лежащим в основе этого репозитория.

### Что такое контейнеризация на самом деле

Контейнеризация — это упаковка приложения вместе со всеми его зависимостями (библиотеками, настройками, версией языка) в единый стандартизированный блок — контейнер. Цель — чтобы код работал одинаково везде. Docker — самый популярный инструмент для сборки и запуска таких контейнеров.

### Контейнер vs виртуальная машина

Классический вопрос на собеседованиях и экзаменах:

- **Виртуальная машина** эмулирует виртуальное «железо» и загружает внутрь полноценную тяжёлую операционную систему (Windows/Linux). ВМ весят гигабайты и запускаются минутами.
- **Контейнер** не тянет за собой отдельную ОС — он использует ядро операционной системы хоста, изолируя только процессы самого приложения. Поэтому контейнеры весят мегабайты и запускаются за доли секунды.

### Три кита Docker

- **Dockerfile** — текстовый файл-инструкция (рецепт): какую базовую систему взять, что установить, какой код скопировать и как его скомпилировать/запустить.
- **Образ (Image)** — готовый шаблон «только для чтения», собранный по Dockerfile, сравнимый с установочным диском или слепком. Образы хранятся на диске и никуда не исчезают, пока их не удалят.
- **Контейнер (Container)** — запущенный экземпляр образа: живой процесс в оперативной памяти.

### Работа с файлами и данными

- **`.dockerignore`** — работает так же, как `.gitignore`. Перечисляет файлы и папки, которые не нужно копировать в контекст сборки (кэш, секреты, тяжёлые локальные модули) — это ускоряет сборку и делает образ легче.
- **Тома (Volumes)** — выделенное хранилище, которое переживает удаление контейнера. По умолчанию данные внутри контейнера пропадают вместе с ним; тома позволяют пробросить папку с хоста внутрь контейнера (например, `-v /tmp/.X11-unix:/tmp/.X11-unix`, используется здесь для GUI-примеров) или сохранять данные базы данных между перезапусками.

### Шпаргалка по командам

| Команда | Что делает |
| --- | --- |
| `docker ps` | Список запущенных сейчас контейнеров |
| `docker ps -a` | Список вообще всех контейнеров, включая остановленные |
| `docker images` | Список всех собранных/скачанных образов на машине |
| `docker build -t <name> .` | Собрать новый образ по Dockerfile из текущей папки |
| `docker run --rm <name>` | Запустить контейнер из образа; `--rm` автоматически удаляет его после завершения, чтобы остановленные контейнеры (как в примерах на Pascal, Ruby и Rust) не копились |
| `docker stop <name>` | Мягко остановить работающий контейнер |
